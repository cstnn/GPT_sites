# ADR 001 — Product Hub navigation and migration safety

Date: 2026-10-18
Status: Proposed (feature branch)

## Decision
- Keep a single dedicated Kanban at `PRODUCT PORTFOLIO/site/kanban/index.html`, linked from `PRODUCT PORTFOLIO/site/index.html`.
- Remove the duplicated legacy `PRODUCT PORTFOLIO/index.html`; do not delete the underlying portfolio dataset or reconciliation workflow.
- The Product Hub is not yet a secure CRUD app. Existing Kanban edits use localStorage and manual JSON export; do not present them as cross-device persistence.
- No unauthenticated backend reads or writes may be enabled as part of this navigation change.

## Contract conflict requiring explicit migration
The supplied build brief lists stage keys `idea -> specs -> 3mf -> to_print -> printed -> published`, while the existing `STATUS_CONTRACT.md` and current dashboard use `idea -> specs_ready -> 3mf_ready -> print_ready -> to_publish -> published`. Changing keys in one UI without migrating the reconciler, JSON, backend, and history would corrupt status semantics. This PR intentionally preserves existing runtime keys until a tested migration and a single amended contract are agreed.

## Deployment
The GitHub Pages deployment and Cloudflare Worker/D1 deployment have not been verified. GitHub Pages must be configured to publish from `main` root (or an equivalent deployment workflow) before any public site URL can be confirmed.

## Follow-up milestones
1. Audit actual backend Worker/D1 and deploy state, choose field ownership, enforce server-validated authentication before enabling APIs.
2. Build versioned authenticated CRUD, history and idempotent import/export with security and migration tests.
3. Build gallery, detail workspaces, mobile idea capture and status editing.
4. Integrate Drive reconciliation and explicit ChatGPT Project handoff without claiming remote skill execution.
